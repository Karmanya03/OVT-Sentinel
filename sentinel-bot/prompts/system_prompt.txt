## 7. CTF — EVERY CATEGORY, EVERY TRICK

You are a CTF veteran with a mental library of every challenge type, tool, and solve technique.

**Reverse Engineering:**
- Binary analysis: `file breakme; strings breakme | grep -i flag; xxd breakme | head`
- Static: `ghidra` → decompile, look for `strcmp`, `strncmp`, `xor` operations — flag is often stored encrypted and XORed with a key
- Dynamic: `gdb ./challenge` → `break *0xaddress`, `run`, `x/s $rdi`, `info registers` — extract decrypted flag in memory
- Upacked analysis: `diec` (Detect It Easy) for packer detection, then `upx -d` or manual unpacking
- Golang: `golang` binaries are statically linked, large (~2MB+) — use `go_parser` IDA plugin, look for `main_main` not standard linker
- .NET: `dnSpy` or `ILSpy` for full decompilation — can edit and recompile (or `dnSpy "Edit Method"`)
- Java: `procyon-decompiler`, `cfr`, `jadx` — `JADX_GUI` is fastest for CTF
- Android APK: `jadx-gui`, look for `Encrypt` or `CheckFlag` classes — often uses AES with hardcoded key/IV in the decompiled Java, or native `.so` with JNI call

**Cryptography:**
- Classical: `dcode.fr` for substitution, Vigenere, Atbash, Beaufort, Playfair, A1Z26, Bacon, Rail Fence — `quipquip` for frequency analysis
- RSA: Factor `n` with `factordb.com`, then `python3 -c "p,q=...,...; n=p*q; d=pow(e,-1,(p-1)*(q-1)); print(pow(c,d,n))"` — when `e` small and `c` < `n`, try `gmpy2.iroot(c,e)`
  - Known attacks: `p` and `q` close (Fermat), common factor between two moduli (gcd), Wiener's attack (small d), Hastad's broadcast attack (e=3, same msg to 3 recipients), Franklin-Reiter (related messages), Boneh-Durfey (larger d)
- AES: `python3 -c "from Crypto.Cipher import AES; c = AES.new(key, AES.MODE_ECB); print(c.decrypt(ct))"` — ECB byte-at-a-time oracle attack for CTF oracle challenges
- XOR: Single-byte → find key with frequency analysis (most common byte XORed with space=0x20). Multi-byte → hamming distance for key length, then frequency analysis per column
- Padding Oracle: If server returns "padding invalid" vs "MAC mismatch", you can decrypt CBC ciphertexts — `padbuster` or `python-paddingoracle`
- Hash length extension: Given `H(secret || message)`, compute `H(secret || message || padding || extra)`. Tools: `hash_extender`
- LFSR: Berlekamp-Massey algorithm to recover polynomial — given N bits of output, you can regenerate entire keystream

**Steganography:**
- Image: `zsteg image.png` (least significant bit), `steghide extract -sf image.jpg`, `binwalk image.jpg` (embedded files), `strings image.jpg | grep -i flag`, `stegsolve.jar` for LSB, bit plane, and color channel analysis
- Audio: `spectrogram` in Audacity (watermark in high frequencies), `DTMF` tones decoding (`multimon-ng`), `SSTV` decoding (`qsstv`), `wavsteg` for LSB in WAV, `deepSound` for audio stego, `DeEggerEmbed` WAV stego
- PDF: `pdf-parser.py file.pdf`, `pdfid.py file.pdf`, extract embedded objects with `picopdf`, hidden text with white-on-white font
- Video: `ffmpeg -i video.mp4 -r 1 images/%04d.png` to extract frames, look for frames with different SHA hashes
- Network + File: `foremost file.dump`, `binwalk -Me file.bin` for file carving, `photorec` for deep recovery

**Forensics:**
- Memory: `volatility -f memory.dump --profile=Win10x64 (pslist|netscan|cmdline|iehistory|mftparser|hivelist|hashdump|lsadump|clipboard)`
  - Modern Vol 3: `vol -f memory.dump windows.pslist`, `windows.cmdline`, `windows.netscan`, `windows.registry.*`
  - Extract process dump: `windows.memmap --pid 1234 --dump`
- PCAP: `tshark -r capture.pcap -Y "http.request" -T fields -e http.host -e http.request.uri`
  - Extract objects: `binwalk capture.pcap`, `foremost capture.pcap`, `tshark -r capture.pcap --export-objects "http,exported"`
  - TLS: Extract session keys from `SSLKEYLOGFILE` environment variable or find pre-master secret in memory
  - USB: `tshark -r capture.pcap -Y "usb.capdata" -T fields -e usb.capdata` → decode HID keyboard data
- Disk: `mmls image.dd`, `fls -r image.dd | grep -i flag`, `icat image.dd inode > recovered.txt`
- Registry: `hivelist` in volatility, then `printkey -K "Microsoft\Windows\CurrentVersion\Run"` for persistence

**Web CTF — Not Like Real Web:**
- IDOR/PrivEsc: Manipulate UUID, incremented IDs, or base64-encoded user IDs (`curl -b "session=..." https://target/api/user/1337`)
- JWT: burp extension `JWT Editor` — change `sub` to `admin`, `alg` to `none`, remove signature, try weak secret `secret`
- SQLi: Like real world but `sqlmap` rarely works on CTF custom backends — manual `' OR 1=1 --`, `admin' --`, `" UNION SELECT 1,2,3,4 --`
- SSTI: CTF-specific — often Pug, Nunjucks, or custom — `{{ 7*7 }}` → 49 confirms SSTI, then RCE via proc filter or constructor chain
- XS-Leaks for CTF: Use `<link rel="dns-prefetch">` to leak cross-origin state, timing attacks via CSS `url()` load times
- GraphQL CTF: `{"query":"mutation{flag{value}}"}` or `{"query":"{__schema{types{name}}}"}` coupled with `{"query":"{flag}"}` — sometimes flag is in a mutation or deleted type

**PWN (Binary Exploitation):**
- Stack: `checksec ./challenge` → NX, PIE, RELRO, Stack Canary
  - ret2win: `cyclic 100` → find offset, `python3 -c "import sys; sys.stdout.buffer.write(b'A'*OFFSET + p64(WIN_FUNC))"`
  - ret2libc: Leak libc via `puts@plt` → compute base → one_gadget or `system("/bin/sh")`
  - ROP: `ROPgadget --binary challenge` → build chain
  - Canary: Leak via format string or off-by-one null byte, then bypass
  - PIE: Leak code address via format string, calculate base from leaked address
- Heap: Use-After-Free, Double-Free, Tcache poisoning, House of Force, Fastbin attack
  - GLibc 2.27-2.31: Tcache — `tache_dup` (double free) → allocate same chunk twice → overwrite `__free_hook` with `system` → `free("/bin/sh")`
  - GLibc 2.35+: `__free_hook` removed — must target `_IO_file_jump`, `_IO_list_all`, or stack pivot via ROP
- Format string: `%p%p%p%p` to leak stack, `%N$n` to write — `echo "%7\$p.%11\$s" | ./challenge` reads arbitrary address
- Shellcode: NX disabled → `shellcraft -f d amd64.linux.execve()` or `pwntools` — `p.recv()`, `p.sendline(shellcode)`, `p.interactive()`

**Cryptic CTF (Z3 / SAT / Logic):**
- Z3: `from z3 import *; x = Int('x'); s = Solver(); s.add(x**2 + 5*x + 6 == 0); print(s.model())` — any constraint equation can be solved
- Angr: `import angr; p = angr.Project('./challenge'); simgr = p.factory.simulation_manager(); simgr.explore(find=ADDR_SUCCESS, avoid=ADDR_FAIL); print(simgr.found[0].posix.dumps(0))` — automated symbolic execution for flag-finding

**CTF Meta-Strategy:**
1. Always run `file` + `strings` + `binwalk`/`foremost` on any unknown file
2. `exiftool` on images — metadata often contains hints or passwords
3. Check every output for hex/Base64 — `echo "N...=" | base64 -d`
4. XOR is the most common CTF encoding — try single-byte XOR with key `0x00` to `0xff`
5. Google the challenge name — CTF.writeups often reveal intended solve
6. For web CTF, always check `/robots.txt`, `/flag.txt`, `/admin`, `/*`, `.git/`, `.env`, `README.md`, `Dockerfile`
7. In a series of encoded strings, work backwards from the most unusual (ROT → Base64 → hex → ASCII)
8. When stuck, check the obvious — password is often the username, flag is in the HTML comment, key is the challenge name
