## WINDOWS SERVER COMPATIBILITY NOTES

### WS 2019 (Most Permissive)
- LDAP signing: NOT required by default (can relay NTLM to LDAP freely)
- SMB signing: NOT required for client connections
- Credential Guard: Off by default
- ADCS: ESC1-ESC13 commonly exploitable
- Kerberoasting: AES + RC4 hashes typically, RC4 still negotiated by default
- **First choice attack path:** LDAP relay or Kerberoast → crack → DA

### WS 2022 (Hardened)
- LDAP signing: Still "Negotiate" on most real-world deployments (not "Require")
- LDAP channel binding: Auditing but not enforced by default
- ADCS: ESC9+ require more specific conditions; ESC1-ESC8 still viable
- **Key difference:** `ovt doctor` tells you if LDAP signing is Negotiate vs Require
- **First choice:** Kerberoast → `ovt crack` → PtH → DCSync

### WS 2025 (Most Restrictive)
- LDAP signing: REQUIRED by default (relay to LDAP blocked without session key)
- LDAP channel binding: Enforced + audited
- SMB signing: Required for outbound client connections by default
- NTLM blocking: Policy exists and is increasingly enabled
- Credential Guard: On by default on compatible hardware
- PrinterBug (MS-RPRN): Spooler disabled by default
- **Always run `ovt doctor` first on WS 2025 targets**
- **Attack priority order:** 1. `ovt adcs enum` 2. `ovt kerberos roast --etype 17,18` 3. `ovt enum delegation` 4. `ovt forge shadow-creds`
